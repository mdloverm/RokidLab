- **步骤**：

## 10. 通道仲裁（ARB）

> 背景：手机侧蓝牙栈对「同一设备 + 同一 SCN」只允许一条客户端 RFCOMM 通道。`ChannelArbiter` 以协作式闸门（非互斥锁）按优先级 `BACKGROUND(0) / NORMAL(1) / LONG_LIVED(2)` 仲裁，`acquire()` 永不阻塞、`shouldYield()` 让路。

### ARB-01 [v3.5] 投屏长连接占用通道 + ASR 让路
- **前置**：CHAT 会话已连接，眼镜端正常。
- **步骤**：
  1. 启动手机投屏（或屏幕镜像），保持 ≥30s。
  2. 投屏期间对眼镜说一句语音指令（触发 ASR 上行/下行）。
  3. 停止投屏后，再重复一次语音指令。
- **预期结果**：投屏以 `LONG_LIVED` 占用蓝牙通道并先释放全 App 共享 ADB 会话；ASR 后台轮询检测到存在更高优先级持有者后自动让路（不新建 RFCOMM，走文件兜底补读），语音仍可识别、不报「通道冲突/连接失败」；停止投屏后租约释放，ASR 恢复下行推送。
- **执行结果 / 设备矩阵**：—

### ARB-02 [v3.5][回归] 通道租约幂等与长持有告警
- **步骤**：
  1. 反复启动/停止投屏 ≥5 次。
  2. 保持投屏 >10 分钟。
  3. 观察日志中的 `ChannelArbiter` 快照与租约告警。
- **预期结果**：重复 acquire/release 均安全（幂等），无通道泄漏导致后续 ASR / 文件管理连不上；`LONG_LIVED` 持有超过 10 分钟仅打印告警，不被强制回收。
- **执行结果 / 设备矩阵**：—

## 11. 能力握手与协议（HSK）

> 背景：`GlassesHandshake` 三态语义 —— `supports()` 返回 `null`=尚未握手（乐观放行）、`true`/`false`=已知；眼镜端主动上报 `TOPIC_HELLO`，手机端连接后也下发 `TOPIC_HELLO_REQ`，4s 无应答判为旧版 v1。

### HSK-01 [v3.5] 眼镜端能力三态握手（新版 v2）
- **前置**：v3.5 手机端 + 新版（v2 协议）眼镜端。
- **步骤**：
  1. 建立连接，观察握手日志（`TOPIC_HELLO` / `TOPIC_HELLO_REQ`，`GlassesHandshake.describe()`）。
  2. 触发一次需要确认的外部副作用工具。
- **预期结果**：手机端收到 hello（`version=2` + caps 位掩码）后 `known=true`，`supports(bit)` 按位返回；握手完成前 `supports` 返回 `null` 走乐观路径，不阻塞功能。
- **执行结果 / 设备矩阵**：—

### HSK-02 [v3.5][回归] 旧版眼镜端（v1）4s 快速降级
- **前置**：旧版眼镜端（不应答 hello）混装 v3.5 手机端。
- **步骤**：连接后立即触发一次确认类工具；等待 4s 后再触发一次。
- **预期结果**：发出 `HELLO_REQ` 后 4s 无应答 → `markLegacy`（version=1、caps=NONE、legacy=true），`supports()` 返回 `false` → 走快速降级；不出现每次确认空等 35s；功能不崩、不误判为在线能力。
