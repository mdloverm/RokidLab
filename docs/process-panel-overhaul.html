聊天窗口「过程」改造说明

RokidLab phone-app · 2026-10-10 · 对照大厂 agent 过程面板的逐项覆盖

一、你报的两个问题，根因在哪

问题 1：文件类操作应该是可点开的地址链接。

根因不在 UI，在数据面：一条工具调用的信息只有 AgentStep 一个结构化出口，而它没有文件字段。 路径被拍进 detail 那段「参数 → 结果」的字符串里（上限 240 字符），而 apply_patch／save_code_file 的参数里塞着完整 diff 或源码 —— path 字段在 120 字符内就被顶掉了。所以在数据层就做不到「可点开」，改 UI 没有用。

问题 2：该在过程里的跑到对话窗口了。

事件流里的 14 类事件，有 9 类在「过程」面板里完全没有对应物； 另有「收尾兜底轮」跑工具时全程静默、子代理内层步骤的结果恒为空。 这些信息既然没有过程落点，就只能落进气泡正文。

一句话判据：问「这条回答的是你做了什么，还是结果是什么」—— 前者归过程，后者归对话。过程只有一条结构化出口，缺字段就只能掉进正文。

四、三条不该被改回去的判据

  • 不做通用路径扫描。只认「工具名 → 参数键 + 动作」登记表。 通用扫会把 save_code_file 源码里的 import '../src/a.js' 当成「它操作了这个文件」，也会把「读到路径」误报成「改了它」。
  • 解析不出工作区根就不显示芯片。宁可少一个可点的东西， 也不给一个打不开的路径 —— 后者会让用户以为文件丢了。
  • 产物必须落盘。否则「新会话能看、旧会话不能看」， 比不做更让人怀疑数据丢了。
